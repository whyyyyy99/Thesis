## Knowledge

### Confirmed Static API Mappings
These are predefined pandas-to-Polars mappings from a curated knowledge base. Use them as your primary migration reference.

  SeriesGroupBy.apply → group_by().agg(...) if possible; otherwise map_groups / custom logic  [no direct Polars equivalent — see guidance below]
  pandas.DataFrame.fillna → df.fill_null(...) / pl.col(...).fill_null(...); use fill_nan for NaN  [no direct Polars equivalent — see guidance below]
  pandas.DataFrame.groupby → polars.DataFrame.group_by
    Notes: Groups rows by one or more columns for aggregation.
    Limitations: Use df.group_by(...).agg(...); as_index, level, and index grouping need manual review.
    Discrepancies: pandas can group by index/mapper and has as_index; Polars groups by columns/expressions and has no pandas-style index.
  pandas.DataFrame.melt → polars.DataFrame.unpivot
    Notes: Unpivot a DataFrame from wide format to long format.
    Limitations: Map id_vars to index=, value_vars to on=, var_name to variable_name=, value_name to value_name= in Polars unpivot.
    Discrepancies: pandas melt is aliased to DataFrame.melt; Polars renamed melt to unpivot in version 0.20. Both achieve the same wide-to-long reshape.
  pandas.DataFrame.pivot → polars.DataFrame.pivot
    Notes: Reshape DataFrame from long to wide format using column values as new column headers.
    Limitations: Polars pivot syntax differs: use on= for column, index=, values=, aggregate_function=. No multi-value support like pandas.
    Discrepancies: pandas pivot uses index/columns/values kwargs; Polars uses on/index/values/aggregate_function and does not support multi-value pivoting in the same way.
  pandas.DataFrame.reset_index → No direct Polars equivalent; use with_row_index() only for row numbers  [no direct Polars equivalent — see guidance below]
  pandas.Series.to_list → polars.Series.to_list
    Notes: Returns Series values as a Python list.
    Limitations: Use s.to_list().
    Discrepancies: Both return Python lists, but pandas missing values and Polars null/NaN handling may differ.

### Migration Guidance (for APIs without corpus docs)
For pandas APIs where the confirmed Polars target API was not found in the documentation corpus, the following textual migration notes from the knowledge base may still be helpful. Use them as guidance about the recommended migration approach, but verify correctness against your own knowledge of valid Polars APIs.


SeriesGroupBy.apply:
  Suggested migration: group_by().agg(...) if possible; otherwise map_groups / custom logic
  Notes: Applies a function group-wise.
  Limitations: Prefer native expressions; Python UDF group apply is slower and less optimizable.
  Discrepancies: pandas apply is flexible; Polars requires explicit grouped expressions or custom group mapping.

pandas.DataFrame.fillna:
  Suggested migration: df.fill_null(...) / pl.col(...).fill_null(...); use fill_nan for NaN
  Notes: Fills missing values with a value or method.
  Limitations: Use fill_null for nulls and fill_nan for floating NaN values.
  Discrepancies: pandas fillna covers several missing markers, while Polars distinguishes null from NaN.

pandas.DataFrame.reset_index:
  Suggested migration: No direct Polars equivalent; use with_row_index() only for row numbers
  Notes: Resets index into columns or drops it.
  Limitations: If pandas index contains meaningful values, preserve it as a real column before migration.
  Discrepancies: pandas has hidden index to reset; Polars has no hidden index.

## Knowledge

### Confirmed Static API Mappings
These are predefined pandas-to-Polars mappings from a curated knowledge base. Use them as your primary migration reference.

  pandas.DataFrame.apply → polars.DataFrame.map_rows
    Notes: Applies a function along DataFrame rows or columns.
    Limitations: Avoid direct UDF migration when possible; rewrite as native Polars expressions.
    Discrepancies: pandas apply(axis=...) is flexible, while Polars favors typed expressions and row UDFs are slower.
  pandas.DataFrame.empty → polars.DataFrame.is_empty
    Notes: Checks whether the DataFrame is empty.
    Limitations: Use df.is_empty().
    Discrepancies: Mostly direct, but pandas emptiness also relates to axes.
  pandas.DataFrame.join → polars.DataFrame.join
    Notes: Join columns of another DataFrame on index or on a key column.
    Limitations: Polars join requires explicit on= or left_on=/right_on= columns; index-based join (pandas default) has no equivalent since Polars has no index.
    Discrepancies: pandas join defaults to joining on index; Polars join always requires explicit key columns.
  pandas.DataFrame.set_index → No direct Polars equivalent; keep key columns as normal columns  [no direct Polars equivalent — see guidance below]
  pandas.read_csv → polars.read_csv
    Notes: Reads a comma-separated or delimited text file into a DataFrame.
    Limitations: Most basic CSV options map to pl.read_csv, but pandas-specific options such as index_col, converters, iterator, and some date parsing behavior need manual review.
    Discrepancies: pandas read_csv has broader legacy parsing options; Polars expects stricter CSV input and returns a Polars DataFrame without pandas-style index.

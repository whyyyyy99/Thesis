## Profile

## Rules
- Preserve the original logic and execution flow exactly; change only what is necessary for migration.
- Preserve the observable output contract, including required columns, column order when semantically meaningful, and compatible return type.
- Polars has no row index; handle index-dependent logic explicitly using column operations.
- Do not alter behavior on edge cases such as empty input, null values, duplicate keys, or single-column outputs.
- Prefer vectorised Polars expressions over element-wise operations wherever possible.
- Use valid Polars APIs only; do not copy pandas-only idioms into Polars.
- Include all necessary imports at the top.

  pandas.DataFrame.index → No direct Polars equivalent; use explicit index column or with_row_index()  [no direct Polars equivalent — see guidance below]
  pandas.DataFrame.loc → polars.DataFrame.filter
    Notes: Access a group of rows and columns by label(s) or a boolean array.
    Limitations: Polars has no label-based index; replace df.loc[mask] with df.filter(mask) and df.loc[:, cols] with df.select(cols).
    Discrepancies: pandas loc relies on the Index; Polars is index-free and uses filter/select/slice for the same operations.
  pandas.Series.iloc → polars.Series.__getitem__
    Notes: Selects values by integer position.
    Limitations: Use direct indexing, gather, or slice depending on scalar/list/range selection.
    Discrepancies: pandas .iloc is explicit integer-location API; Polars uses Series positional methods.

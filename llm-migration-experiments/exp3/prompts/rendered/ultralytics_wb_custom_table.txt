## Rules

- Preserve the observable output contract, including required columns, column order when semantically meaningful, and compatible return type.
- Polars has no row index; handle index-dependent logic explicitly using column operations.
- Do not alter behavior on edge cases such as empty input, null values, duplicate keys, or single-column outputs.
- Prefer vectorised Polars expressions over element-wise operations wherever possible.
- Use valid Polars APIs only; do not copy pandas-only idioms into Polars.
- Include all necessary imports at the top.

Data structure also contains labeled axes (rows and columns).
Arithmetic operations align on both row and column labels. Can be
thought of as a dict-like container for Series objects.
  pandas.DataFrame.round: Round numeric columns in a DataFrame to a variable number of decimal places.

Number of decimal places to round each column to. If an int is
given, round each column to the same number of places.
Otherwise dict and Series round to variable numbers of places.

pandas.DataFrame:
  Suggested migration: polars.DataFrame
  Notes: Creates a two-dimensional tabular data object.
  Limitations: Use pl.DataFrame(data, schema=...); pandas index has no direct Polars equivalent.
  Discrepancies: pandas DataFrame has row index labels, while Polars DataFrame only has columns and row positions.

pandas.DataFrame.round:
  Suggested migration: df.select(pl.all().round(decimals)) / pl.col(...).round(...)
  Notes: Rounds numeric columns.
  Limitations: Use round; dictionary-per-column decimals need explicit column expressions.
  Discrepancies: pandas supports per-column decimals dict; Polars requires explicit expressions.

import pandas as pd

def before_binned_unbinned(
    appraised: pd.DataFrame,
    pipe_read: pd.DataFrame,
    output_columns: list,
) -> tuple:
    binned = (appraised[appraised["binned"]]
              .drop(["divergence","binned"], axis=1)
              .reset_index(drop=True))
    unbinned = pipe_read.join(
        appraised.set_index(output_columns[0:-1]),
        on=output_columns[0:-1],
    )
    unbinned = (unbinned[~unbinned["binned"].fillna(False)]
                .drop(["divergence","binned"], axis=1)
                .reset_index(drop=True))
    unbinned["found_in"] = None
    return binned, unbinned

### Confirmed Static API Mappings
These are predefined pandas-to-Polars mappings from a curated knowledge base. Use them as your primary migration reference.

  pandas.DataFrame → polars.DataFrame  [doc not in corpus — see guidance below]
  pandas.DataFrame.drop → polars.DataFrame.drop
    Notes: Drops specified row or column labels.
    Limitations: Column dropping maps to df.drop; row-label dropping needs explicit index column logic.
    Discrepancies: pandas can drop row/index labels, while Polars drops columns or filters rows explicitly.
  pandas.DataFrame.join → polars.DataFrame.join
    Notes: Join columns of another DataFrame on index or on a key column.
    Limitations: Polars join requires explicit on= or left_on=/right_on= columns; index-based join (pandas default) has no equivalent since Polars has no index.
    Discrepancies: pandas join defaults to joining on index; Polars join always requires explicit key columns.
  pandas.DataFrame.reset_index → No direct Polars equivalent; use with_row_index() only for row numbers  [no direct Polars equivalent — see guidance below]
  pandas.DataFrame.set_index → No direct Polars equivalent; keep key columns as normal columns  [no direct Polars equivalent — see guidance below]
  pandas.Series.fillna → polars.Series.fill_null
    Notes: Fills missing values with a value or method.
    Limitations: Use fill_null for nulls and fill_nan for floating NaN values.
    Discrepancies: pandas fillna covers several missing markers, while Polars separates null from NaN.

### Migration Guidance (for APIs without corpus docs)
For pandas APIs where the confirmed Polars target API was not found in the documentation corpus, the following textual migration notes from the knowledge base may still be helpful. Use them as guidance about the recommended migration approach, but verify correctness against your own knowledge of valid Polars APIs.


pandas.DataFrame:
  Suggested migration: polars.DataFrame
  Notes: Creates a two-dimensional tabular data object.
  Limitations: Use pl.DataFrame(data, schema=...); pandas index has no direct Polars equivalent.
  Discrepancies: pandas DataFrame has row index labels, while Polars DataFrame only has columns and row positions.

pandas.DataFrame.reset_index:
  Suggested migration: No direct Polars equivalent; use with_row_index() only for row numbers
  Notes: Resets index into columns or drops it.
  Limitations: If pandas index contains meaningful values, preserve it as a real column before migration.
  Discrepancies: pandas has hidden index to reset; Polars has no hidden index.

pandas.DataFrame.set_index:
  Suggested migration: No direct Polars equivalent; keep key columns as normal columns
  Notes: Sets DataFrame index using existing columns.
  Limitations: Do not translate to df.set_index; use key columns explicitly for joins, grouping, sorting, or filtering.
  Discrepancies: pandas hides key columns in an index, while Polars keeps keys as columns.
